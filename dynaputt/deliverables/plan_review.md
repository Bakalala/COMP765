# Review of the original LLM task plan

Reviewed version: `LLM_TASKS.md` as of November 5, 2026, before this revision, against
the code, both result sets, the report, the demo, and the course requirements. Both
CSVs were regenerated byte for byte, and the demo was run in a browser.

**Verdict: revise first.** The results table and the "every paired seed" claim were
accurate, and the plan protected student-owned work. But it would have sent assistants
to write up an interpretation the data does not support, and it missed a broken demo.

## What was accurate

- All 18 table values match `results/summary.csv` and the episode CSV.
- 20 updates beat 5 on both courses in all five paired seeds.
- The archive has a different Easy ordering and is kept separate.
- Name, reflection, and the Mac check stay with the student.

## Factual errors

1. **"Protocol sensitivity" is unsupported (lines 57-59, 212, 234).** With 100 new seeds,
   5- and 20-update thresholds on Easy are 56.9 / 53.5 with separate streams and
   56.4 / 52.7 with a shared stream. Five-seed resamples reverse the order 12-21% of the
   time. The reversal is best explained by noise. See `results/extended/summary.md`.
2. **The stale-file list is incomplete (lines 31-33).** It omits
   `results/experiment_summary.md:19-20` and `summarize_results.py`, which hard-code "not
   monotonic" (false for the primary run), plus `REPORT_OUTLINE.md:15` and `README.md`,
   which says the demo trains "the setting used in the experiment".
3. **The report's staleness was understated (line 32).** Beyond old numbers,
   `build_report.py` stated that one generator is used for both purposes (old lines 581
   and 624), which contradicts `agents.py`. `audit.md` said the same.
4. **"Final greedy success" hides what it is (line 45).** It covers checkpoints after
   episodes 301-350. The 0.400 is 100/250, with each seed at 17-24 of 50 and none stable.
   It reads like two solved seeds, but the policy is still flipping.
5. **The demo was treated as unchecked but sound (line 36).** It was broken. The page
   loaded finished ("5 / 20" strokes), so "Take shot" did nothing, and `draw()` threw
   "number 1 is not iterable" on load and on Reset, so no ball was drawn
   (`index.html`, old lines 207-217, 221, 260, 296).
6. **Demo stream not covered (line 114).** Task 1 asks about random streams in Python
   only. The demo uses one shared stream.

## Scientific gaps the plan could not surface

7. **Metric mismatch.** The question says "fewer real shots" (line 11) but every metric
   counts episodes. The CSV already held `training_strokes`.
8. **Optimistic initialization.** Q starts at 0 and all returns are negative. No task
   asks about this, and "whether updates are matched" (line 117) does not reach it. It
   turned out to be the most important confound (see `analysis_notes.md`).
9. **Small effective problem.** Only 15 of 54 and 23 of 56 cells are reachable.

## Missing or ambiguous actions

- No owner for `summarize_results.py`, `README.md`, or `REPORT_OUTLINE.md`: task 4
  forbids code edits, task 5 owns only the report, and task 7 forbids changing claims.
- Task 6A's failures have no route back. Nothing consumes `report_review.md`, and task 7
  says not to change claims.
- Tasks 6A, 6B, and 7 lack "Done when" criteria. Task 4's "handoff note" has no path.
- Task 3 needs lecture notes that are not in the folder, and `literature_notes.md`
  already says they were inaccessible. It should say what to do then.
- Task 3 omits Scannell et al. (2025), though the report cites it.
- Task 5 needs `reportlab`, which was not in `requirements.txt`.
- Line 64 calls packets "read-only" although each writes a file.

## Sequencing conflicts

- Lines 73-74 start the demo refresh after report claims freeze; line 271 starts it after
  task 4. If it runs early, it can quote results the report later changes.
- Tasks 4 and 6B both edit `demo_plan.md`, which is safe only in strict order.

## Gaps against the course requirements

- Deadline missing: December 3, 9pm, as the My Courses assignment "Final Project".
- Peers: the requirements ask for comparison with peers' papers. No task or student
  action covers it.
- Station format: "1-2 slides or some videos" is not planned. Task 6B covers a talk only.
- Method depth: no task recaps Sutton's paper or asks for technical support.
- Improvement proposal: encouraged by the requirements, absent from the tasks.
- Task 5's section list omits lessons, surprises, and open questions.

## How each was handled

All of the above were fixed in this revision or moved to `LLM_TASKS.md` as an open item.
